# Промпт: мобильное приложение для учёта инвестиционного портфеля

> Скопируйте текст ниже (от «Роль» до конца) и отдайте его ИИ-ассистенту или разработчику.
> Промпт написан в той же манере, что и приложение «Расходы» из этого репозитория:
> офлайн-PWA, один `index.html`, без сборки и сервера. Если нужен нативный вариант —
> см. раздел «Альтернатива: нативный стек» в конце.

---

## Роль

Ты — опытный фронтенд-разработчик и продуктовый дизайнер мобильных финансовых приложений.
Твоя задача — спроектировать и реализовать мобильное приложение «Портфель» для личного
учёта инвестиций: акций, облигаций, фондов (ETF/ПИФ), криптовалюты, депозитов и валюты.

## Цель продукта

Частный инвестор должен за 10 секунд понять:
1. Сколько сейчас стоит весь портфель и сколько он заработал/потерял (в деньгах и в %).
2. Как распределены деньги по классам активов, валютам и брокерским счетам.
3. Какие позиции растут, какие падают, и отклоняется ли портфель от целевой структуры.

Приложение — дневник инвестора, а не торговый терминал: оно **не совершает сделок** и не
подключается к брокеру напрямую. Все данные вводит пользователь (вручную или импортом).

## Технические ограничения

- **Платформа:** Progressive Web App, устанавливается на главный экран iOS/Android.
- **Архитектура:** один файл `index.html` (HTML + CSS + ванильный JS, без фреймворков и сборки),
  плюс `manifest.webmanifest`, `sw.js` и иконки.
- **Офлайн-first:** Service Worker кэширует оболочку приложения; всё работает без интернета.
  Интернет нужен только для необязательного обновления котировок и курсов валют.
- **Хранение:** IndexedDB (основные данные) с резервным `localStorage` для настроек.
  Все чтения/записи обёрнуты в `try/catch`; при недоступности хранилища — понятное предупреждение.
- **Без бэкенда и аккаунтов.** Данные не покидают устройство, кроме запросов котировок.
- **Деньги:** никаких `float` для сумм. Храни суммы в минимальных единицах (копейки/тиыны/центы)
  как целые числа, количество бумаг — строкой-десятичной или целым с масштабом (для крипты до 8 знаков).
- **Язык интерфейса:** русский; форматирование чисел и дат через `Intl.NumberFormat` / `Intl.DateTimeFormat`
  с локалью `ru-RU`.

## Модель данных

```
Account      { id, name, broker, currency, type: 'broker'|'iis'|'bank'|'crypto'|'cash', archived }
Asset        { id, ticker, name, class: 'stock'|'bond'|'etf'|'fund'|'crypto'|'deposit'|'currency'|'other',
               currency, exchange?, isin?, sector?, country?, faceValue? (облигации), maturityDate? }
Transaction  { id, accountId, assetId?, date, type, quantity?, price?, amount, fee, currency, note }
               type: 'buy'|'sell'|'dividend'|'coupon'|'deposit'|'withdraw'|'fee'|'tax'|'split'|'transfer'
Price        { assetId, date, price, source: 'manual'|'api' }
FxRate       { date, base, quote, rate }
TargetAlloc  { key (класс актива / тикер), targetPercent }
Settings     { baseCurrency, theme, hideAmounts, lastBackupAt, priceApi }
```

Позиции (количество, средняя цена, стоимость) **не хранятся**, а вычисляются из транзакций —
так история всегда консистентна. Для ускорения допускается кэш, пересчитываемый при изменениях.

## Расчёты (обязательно покрыть тестами в `tests.html` или через `console.assert`)

- **Количество и средняя цена позиции** — метод FIFO по умолчанию, в настройках можно выбрать
  «средневзвешенная». Учитывай комиссии в себестоимости.
- **Реализованная прибыль** при продаже, **нереализованная** по текущей цене.
- **Доход от выплат:** дивиденды и купоны отдельно, с учётом удержанного налога.
- **Доходность портфеля:** простая (P&L / вложено) и **XIRR** (учёт времени и размеров пополнений).
  Реализуй XIRR методом Ньютона с запасным методом бисекции.
- **Мультивалютность:** все итоги пересчитываются в базовую валюту (выбирается: KZT, RUB, USD, EUR и др.)
  по курсу на дату. Показывай отдельно валютную переоценку.
- **Сплиты** корректно меняют количество и цену без влияния на стоимость.
- **Облигации:** цена в % от номинала, НКД вводится вручную, дата погашения, доходность к погашению (упрощённо).

## Экраны

1. **Обзор (главный)**
   - Крупно: стоимость портфеля в базовой валюте, изменение за день и за всё время (₸/₽/$ и %).
   - Переключатель периода: 1Н / 1М / 3М / 1Г / Всё; линейный график стоимости vs. вложенных средств.
   - Кольцевая диаграмма распределения по классам активов (тап → по валютам / по счетам / по секторам).
   - Топ-3 роста и топ-3 падения.
   - Кнопка «Скрыть суммы» (глаз) — маскирует все суммы для использования на людях.
2. **Позиции** — список с тикером, количеством, стоимостью, P&L в % (зелёный/красный + знак ▲▼,
   не только цвет). Сортировка и фильтры по счёту и классу. Тап → карточка актива: график цены,
   средняя цена, история сделок, полученные выплаты.
3. **Операции** — лента транзакций по датам, поиск, фильтры. Свайп — редактировать/удалить
   (с отменой через тост «Отменить» 5 секунд).
4. **Добавить операцию** — плавающая кнопка «+». Форма адаптируется под тип операции;
   поиск тикера по уже введённым активам, быстрый ввод «Купил 10 SBER по 280». Автоподстановка
   последней цены и счёта. Валидация: нельзя продать больше, чем есть.
5. **Выплаты** — календарь дивидендов и купонов, сумма за месяц/год, график по месяцам.
6. **Ребалансировка** — целевые доли по классам/активам, текущие доли, отклонение,
   подсказка «докупить X на сумму Y», чтобы вернуться к цели при заданной сумме пополнения.
7. **Настройки** — базовая валюта, счета, тема (системная/светлая/тёмная), метод расчёта
   себестоимости, источник котировок, экспорт/импорт, PIN-код на вход, удаление всех данных.

## Котировки и курсы

- По умолчанию — ручной ввод цены (кнопка «Обновить цену» в карточке актива).
- Опционально: загрузка с публичных API (например, MOEX ISS для бумаг Мосбиржи,
  CoinGecko для криптовалют, открытые API курсов валют). Источник — настраиваемый адаптер
  `fetchPrice(asset) → {price, date}`; ошибки сети не ломают приложение, показывается дата последней цены.
- Никаких API-ключей в коде; если источнику нужен ключ — пользователь вводит его в настройках.

## Импорт / экспорт

- Экспорт всех данных в JSON (полный бэкап) и CSV (операции).
- Импорт JSON-бэкапа с предпросмотром и выбором «заменить» / «объединить».
- Импорт CSV с сопоставлением колонок (дата, тикер, тип, кол-во, цена, комиссия, валюта).
- Напоминание сделать бэкап, если последний был > 30 дней назад.

## Безопасность и приватность

- Необязательный PIN (хэш через `crypto.subtle` SHA-256 с солью), автоблокировка при сворачивании.
- Режим скрытия сумм.
- Нет аналитики, трекеров и сторонних скриптов, кроме шрифтов и (опционально) одной
  библиотеки графиков с CDN, закэшированной Service Worker'ом. Предпочтительно — свои SVG-графики.

## Дизайн

- Mobile-first, ширина контента до 560 px, отступы по краям 14–16 px, зоны нажатия ≥ 44 px.
- Учитывай `safe-area-inset-*` (вырез и «чёлка»).
- Цвета — CSS-переменные в `:root`, тёмная тема через `prefers-color-scheme` и `[data-theme]`.
- Шрифты: Onest (текст) и Unbounded (заголовки), цифры — `font-variant-numeric: tabular-nums`.
- Нижняя навигация из 4–5 вкладок; плавные, но короткие анимации (≤ 200 мс),
  уважай `prefers-reduced-motion`.
- Доступность: контраст WCAG AA, `aria-label` у иконок, рост/падение помечаются не только цветом.
- Пустые состояния с подсказкой «Добавьте первую покупку» и кнопкой демо-данных.

## Порядок работы

1. Сначала опиши структуру данных и функции расчёта; покажи их тесты на примерах
   (покупка → докупка → частичная продажа → дивиденд → сплит).
2. Затем сверстай экраны на демо-данных.
3. Подключи хранилище, импорт/экспорт, Service Worker.
4. В конце — котировки из API, PIN и полировка.

На каждом шаге присылай рабочий код целиком для изменённых файлов и кратко перечисляй,
что сделано и что осталось.

## Критерии готовности

- [ ] Приложение устанавливается как PWA и полностью работает в авиарежиме.
- [ ] Расчёты P&L, средней цены и XIRR совпадают с эталонными примерами в тестах.
- [ ] Мультивалютный портфель корректно сводится в базовую валюту.
- [ ] Бэкап JSON → очистка данных → восстановление даёт идентичный портфель.
- [ ] Нет горизонтальной прокрутки на ширине 360 px; тёмная тема без «белых пятен».
- [ ] Lighthouse: PWA — пройдено, Accessibility ≥ 90, Performance ≥ 90.

## Альтернатива: нативный стек

Если нужно приложение в App Store / Google Play, замени раздел «Технические ограничения» на:

- **Flutter 3** (Dart) или **React Native + Expo** (TypeScript) — выбери один и обоснуй.
- Локальная БД: SQLite (`drift` / `expo-sqlite`), миграции схемы.
- Суммы — `Decimal`-тип (`decimal` в Dart, `decimal.js` в TS).
- Архитектура: слои data / domain / presentation, управление состоянием — Riverpod / Zustand.
- Графики: `fl_chart` / `victory-native`.
- Биометрия для входа (Face ID / отпечаток), виджет на главный экран с итогом портфеля.
- Юнит-тесты domain-слоя (расчёты), виджет/компонентные тесты ключевых экранов.
